# Textbook checkpoint: explicit conventions and correlated guard counts

This is an additive editorial checkpoint, not a stable-release declaration.
Frozen preview data, predecessor answers and previous reviews remain unchanged.
The mathematical reader and Lean companion track still share one core registry,
one family/split assignment and the same frozen graph identities.

## A corrected premise needs a visible contract revision

An answer repair cannot fix a false active convention. The first question
correction now has two narrowly bounded payload schemas:

- `qcb.textbook_question_successor.v1`: change the question only.
- `qcb.textbook_question_successor.v2`: change the question and explicitly replace
  its convention list. This is still question version 2, not another correction.

Both bind the complete predecessor and candidate, old and new nine-field
contracts, full answer/rubric/exposition, source evidence and a distinct
content-bound review. The second schema additionally binds both literal
convention lists and a separate substantive convention-change assessment.
Neither can override assumptions, family, split, graph version, target/support
nodes or source references. Neither allocates a new core.

The reader places current conventions before the question. The superseded
convention list is audit-only in the folded revision panel, not active premises;
a question may quote a historical claim to assess or refute it. Browser checks inspect
that separation in every supported theme at mobile and desktop widths, without
opening the solution. A Lean proposal using the predecessor contract is stale;
passing an older proof never upgrades the target automatically.

## LA219: the actual producer, not independent Boolean flags

The [LA219 successor](../shared/repairs/la-219-correlated-guard-question-convention-successor.json)
corrects both a question and its active convention. Its
[distinct exact-content review](../reports/textbook-v1/repairs/la-219-correlated-guard-question-convention-successor-review.json)
is separate from the earlier private mathematical proposal review.

For the actual positive-scale stored Hermite raw-source producer, put
`M = 2^n` and let `c` be its compiled cutoff, with `0 <= c <= M`.
At the stage with remaining width `r`, the span is `s = 2^r` and the parent
start is `p = 2s floor(c/(2s))`. Its children start at `p` and `p+s`.
Writing `c = 2sQ + u`, with `0 <= u < 2s`, shows:

- The right child's full-interval condition would require `2s <= u`, so it
  never enables an injection.
- The left child's condition is `s <= u`, precisely bit `r` of `c`.

Consequently the same-run exponential-call ledger is
`E = n + 2 + popcount(c)`. Its sharp attainable set is `{2, 3}` when `n = 0`,
and every integer from `n+2` through `2n+2` when `n >= 1`.
The top cutoff `c = 2^n` has population count one, not `n+1`.

Attainability uses legal scale inputs, not arbitrary tables. For cutoff zero,
choose `L = 1/pi`. For an integer `1 <= c <= M`, choose
`pi L = M/(M-c+1/2)`; the ceiling argument becomes `c-1/2`, hence returns `c`.
Cutoffs `2^g-1` realize each population count `g = 0,...,n` when `n >= 1`.

The existing Lean loose cap `3n+4` remains valid, but is unattainable on these
legal inputs. Its theorem did not claim sharpness. The stronger population-count
and attainability argument above is reviewed natural-language mathematics;
**no new Lean theorem or native formal view is claimed**. These are exact-real
primitive call counts, not exponential evaluation time, total classical runtime,
normalization cost or state-preparation gate complexity.

## Revalidation is not an approval transplant

Twelve earlier accepted repair reviews bound the entire executable admission
policy as if it were a mathematical source. Changing that policy correctly
invalidated their source bindings. Their authors' mathematical candidates,
historical findings and previous reports were not rewritten.

New distinct-author reviews reconstruct those exact candidates and disclose
prior exposure and primary-source access limits. Mathematical source checks
bind the operative sources; inspected engine hashes and test observations are
recorded separately as historical mechanical context. Removing an old code hash
alone is not a new mathematical review. The current policy points to the new
reports while preserving the old records for audit.

These revalidations add no mathematical cores, change no frozen split, and grant
no global semantic-deduplication or independent held-out-evaluation clearance.
Existing shared subproofs, including BE004/BE112 and plan319/plan407, still need
the stated reconciliation before any incompatible pooling or independence claim.

## Compatible continuation

Non-Lean contributors can review the actual producer mathematics, propose
bounded corrections and develop graph-grounded explanations without installing
Lean. If a convention is wrong, use the explicit convention-aware contract
path; do not quietly reinterpret it in the answer.

Lean contributors attach a view to the current exported contract. For LA219,
formalizing the correlated-guard/population-count and scale-attainability
bridges would be additional work. Applying the old loose-bound lemma certifies
only that bounded subclaim, not the sharp current question.

The reader now retains 177 active core IDs and 36 reserved corrections from the
original 213 obligations. Only three native library-lemma formal companions
are admitted; they are not new exercises or deep proof-search results. Global
semantic reconciliation remains incomplete, isolated model-output evaluation
remains environment-blocked, and model baselines remain unmeasured. Stable
promotion must wait for its actual gates, not a version-label change.
