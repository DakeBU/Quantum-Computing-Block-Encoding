# Native NL dataset card — successor of corrected release-v3

This card supplements, and does not overwrite, the historical DATASET_CARD.md.
The native task is mathematical knowledge/reasoning in ordinary language. It does
not require the reader to know a theorem/declaration name, file path, tactic or
formal syntax. Formal-source identities stay in metadata for inspection.

## Version and counting

`nl-v1` starts with 50 authored candidate **records**. Actual independent semantic
core review can identify duplicates, existing views or uncertainty; those are not
50 established new problem cores. Follow-up `nl-v2`, `nl-v3` batches add genuinely
different mathematical mechanisms and retain rejected originals/review history.
Counts by topic, reviewed semantic step depth and evidence relation are generated
in each version's summary and coverage reports. Several hundred reviewed cores
and broad primary-target coverage remain the persistent goal, not a completed
claim at this initial milestone.

## Evidence and provenance

- Local-source supported: complete local mathematical declarations/definitions
  inspected, not newly compiled.
- NL bridge: original multi-step derivation or counterexample from those sources,
  without claiming a pre-existing formal counterpart for the complete argument.
- Primary-source NL-only: planned/unformalized material with an inspected primary
  text, exact PDF/version/hash/pages/theorem anchors and original explanations.
- Genuine independent fresh-context AI review is identified as AI review, not
  human validation or proof of real-world independence. Author and reviewer are
  distinct contexts; per-item authored digests bind exactly what was read.
- No new local Lean verification was performed. Original release-v3 reference
  evidence is inherited only with its original provenance and never promoted.

Unresolved mathematics, incomplete premises, duplicate solution cores and open
problems do not enter released gold. A finite numerical check is a witness check,
not a proof of a parametric theorem. Imports/ownership are graph structure, not
entailment. Conditional transports retain AND inputs and failure boundaries.

## Canonical cores and splits

One mathematical core is intended across NL, Lean/hybrid views and trivial
parameter/paraphrase variants. Reviewer aliases union related views; target and
family unions bind to frozen legacy assignments without rewriting old splits.
A new composition that bridges incompatible old splits is quarantined to public
diagnostic test and visibly flagged, not silently assigned to training. Shared
foundational support can appear across splits. Primary targets and incidental
support nodes are counted separately.

Core IDs/families are coordination proposals pending a real acknowledgment from
the Lean-equipped collaborator; `integration_allowed=false` until that response
exists. No identity/approval is invented. See the explicit handoff packet.

Tests and reference answers are public grouped diagnostics, not blind, secret,
unseen or contamination-free evaluation. Pretraining exposure is unknown. A new
private assessment needs separate authorized storage and release governance.

## Scoring

Reuse the existing content-rubric scorer. Exact formats can be graded exactly;
NL proofs/explanations require real evaluator marks bound to item/prediction
hashes, required hypotheses and separate fidelity judgments. Copied reference
text does not automatically receive rubric credit. Uncertain ratings stay
ungraded. Software fixtures and reference-copy tests are never model results.
No model judge is called or described as calibrated; no paid baseline is run.

## Reuse and privacy

Original questions, explanations, rubrics and new code use repository MIT terms.
This does not relicense external textbooks or grant their training-data reuse.
Only original mathematical explanations are distributed, not PDFs or long source
proof text. External-source copyright/license and quote permissions remain with
the owners; reuse records describe this narrow original-authoring policy rather
than a blanket permission claim. Access/source-rights uncertainty stays typed.
Credentials, private evaluator answers/logs, raw model generations and copyrighted
primary downloads remain outside the public release tree.

## Known limits

Source review is fallible; reviewed steps are inspectable labels, not universal
PRM truth. Structural graph distance stays unknown and is never a difficulty
label. The full universe has dispositions but not universal meaningful QA. Some
candidate wording may still need mathematical/native-language repair; those stay
provisional. Missing local Lean is not a blocker for this NL goal, and no system
package, Lean, Lake or container runtime is installed by the task.
