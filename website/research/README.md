# QuantumComputinglib: structure, research and publication

These authored records are shared by the reader, the graph lenses and bounded
agent retrieval. They are not a second Lean theorem database.

| Reader route | Canonical input | Evidence boundary |
| --- | --- | --- |
| `mathematical-methods/` | `atlas.json` families | Authored mechanisms with exact named Lean substrates |
| `functor-hypergraph/` | `atlas.json` hyperedges / contributions | Conjunctive conceptual transports and pinned module/import deltas |
| `state-preparation-wiki/` | `state-preparation-wiki.json` | Research targets with access/error/resource and same-model lower-bound contracts |
| `progress/` | Existing chapters, implementation map, papers and Wiki | Generated local/route scope and residual obligations, not manual completion percentages |
| `research-protocol/` | `docs/theorem-publication-protocol.md` | Quantum-specific source-faithful publication discipline |

`data/lean-graph.json` remains the generated module-import and declaration
ownership graph. Curated views reuse its exact identities; they do not mutate
its edges or claim elaborated theorem dependencies. No conceptual transport is
currently certified as a categorical functor. All its tails are required
together. The contribution classes add-node, shortcut, reorganisation and bridge
are explanations of a pinned repository delta, not automated novelty judgements.

## Read a bounded context packet

```bash
python3 website/scripts/research_atlas.py context --route spw-envelope
python3 website/scripts/research_atlas.py context --query "polynomial rank normalization"
```

Retrieve structural hypotheses, exact local declarations, failure boundaries,
conditional transport maps and the next acceptance target before constructing a
new route. An imported paper reference is not a local Lean proof; metadata-only
and unavailable primary sources retain their explicit audit status.

## Publish a contribution

Read `AGENTS.md`, `HARNESS.md`, `docs/theorem-publication-protocol.md` and
`.agents/prompts/mathematical-contribution.md`. Changed production modules require
content-bound source/lesson/assumption/obligation mappings and genuinely distinct
source-blind decoding and anti-anchored review. `publications.json` starts empty:
this reader extension adds no production Lean theorem and does not retroactively
clear historical source-audit debt.

```bash
python3 website/scripts/research_atlas.py check
python3 -m unittest website.scripts.test_research_atlas
python3 website/scripts/check_research_publications.py --base BASE_COMMIT
bash scripts/build-all.sh
```

The normal website gate regenerates all views, validates exact graph identities,
internal/source links and source digest, and runs CI browser checks for MathJax,
mobile/desktop layouts, reading themes, search, keyboard selection, exact-node
focus, complete AND tails and diagram export. Diagrams and long formulas scroll
inside their panels, not the whole mobile page. Screenshots are review artifacts;
the browser script does not pretend to perform a human visual judgement.

The Pages pipeline may reuse only an actually passed proof tree whose complete
source/configuration digest and module inventory match. If its old artifact has
expired, `restore_published_blueprint.py` retrieves the unchanged live Blueprint,
checks its pinned input version and internal links, and preserves the original
proof-execution lineage. Reader reconstruction is fresh; inheritance is never
reported as a fresh Lean execution. A post-deployment check verifies the live
commit, navigation, canonical data and all research routes.
