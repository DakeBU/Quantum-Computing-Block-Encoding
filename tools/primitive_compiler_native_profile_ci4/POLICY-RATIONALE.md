# CI4 self-only namespace contract

Read date: 2026-10-17 (Asia/Shanghai). This is a versioned ENV instrumentation policy correction, not a mathematical or trust-policy admission.

Under the same upstream-Linux implementation assumption already used in CI3, self alone suffices to recognize the initial cgroup namespace:

1. [fs/nsfs.c: ns_get_name](https://github.com/torvalds/linux/blob/v6.12/fs/nsfs.c) gets the requested task's namespace through its namespace operations and renders its name and inode.
2. [kernel/cgroup/namespace.c: cgroupns_operations and cgroupns_get](https://github.com/torvalds/linux/blob/v6.12/kernel/cgroup/namespace.c) supplies that task's actual cgroup namespace. It does not define namespace identity by comparison with PID1.
3. [include/linux/proc_ns.h: PROC_CGROUP_INIT_INO](https://github.com/torvalds/linux/blob/v6.12/include/linux/proc_ns.h) reserves 0xEFFFFFFB (4026531835). [kernel/cgroup/cgroup.c: init_cgroup_ns](https://github.com/torvalds/linux/blob/v6.12/kernel/cgroup/cgroup.c) uses it for the initial namespace and associates that namespace with init_css_set.
4. A new cgroup namespace uses ns_alloc_inum in [namespace.c](https://github.com/torvalds/linux/blob/v6.12/kernel/cgroup/namespace.c); [proc_ns.h](https://github.com/torvalds/linux/blob/v6.12/include/linux/proc_ns.h) routes that to proc_alloc_inum. [fs/proc/generic.c: PROC_DYNAMIC_FIRST and proc_alloc_inum](https://github.com/torvalds/linux/blob/v6.12/fs/proc/generic.c) allocate at or above 0xF0000000, disjoint from the reserved initial value. A namespace install refers to the namespace object; it does not invent another identity with the initial reserved value.

Therefore the observed self readlink `cgroup:[4026531835]` identifies initial cgroup namespace in this narrowly recognized implementation. PID1 agreement is not a logical premise. CI3's additional PID1 accessibility requirement was stronger than this rationale needs; removing it in a new schema is not treating a failed read as successful. CI4 never requests that interface, never substitutes self for PID1, and records only an explicit NOT_REQUESTED_NOT_REQUIRED marker with null value. No sudo, alternate PID, forbidden-interface read or permission bypass is used.

The separate [cgroup API root/view specification](https://docs.kernel.org/admin-guide/cgroup-v2.html#the-root-and-views) associates initial cgroup namespace with the real root; a virtual namespace's apparent root is insufficient. The [memory interfaces](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory-interface-files) remain non-root-only. Unique cgroup2 mount, mount root `/`, actual mandatory self reserved-init observation, actual non-root ancestor file reads and mandatory real-root core observations remain required. A dynamic/unknown self, equal virtual self/PID1 fixture, hidden mount, root-only process, missing non-root field, or inadequate measured headroom is refused.

Limits remain explicit: this is an implementation fingerprint checked against upstream v6.12, not a universal stable-ABI promise or attestation of the actual runner kernel binary, hostile procfs, atomic hierarchy snapshot, or reserved memory. A different identifier fails closed. The CI3 artifact's successful self readlink supports only that one observation; the run failed before non-root memory/root applicability accounting, so no complete memory gate or fresh compilation is inferred.
